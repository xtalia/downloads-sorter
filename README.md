# Downloads Sorter — всё по полочкам

Самодостаточные скрипты для **Windows XP+**, **Windows 10–11**, **Linux**, **macOS** и универсальный вариант на **Python**.

## Как пользоваться

1. Положил скрипт в нужную папку — например, «Загрузки».
2. Запустил скрипт.
3. Всё рассортировано.
4. ???
5. Всё по красоте раскинуто по полочкам.

**Каждый вариант — один файл.** Без `categories.txt`, конфигов и соседних скриптов. Категории встроены. Обычный запуск **сразу перемещает файлы в папке самого скрипта**, без параметров и подтверждений.

## Скачать

[Последний релиз](https://github.com/xtalia/downloads-sorter/releases/latest): три платформенных ZIP и отдельный универсальный `sort-downloads.py`.

| Система | Какой файл взять | Что требуется |
|---|---|---|
| Windows 10–11 | `sort-downloads.bat` | Штатный Windows PowerShell 5.1 |
| Windows XP и новее | `sort-downloads-legacy.bat` | Штатный Windows Script Host / JScript |
| Linux | `sort-downloads.sh` | Bash 3.2+ и стандартные утилиты `mv`, `mkdir`, `tr` |
| macOS | `Sort Downloads.command` | Системный `/bin/bash` 3.2+ |
| Windows / Linux / macOS с Python | `sort-downloads.py` | Python 3.8+, только стандартная библиотека |

В Windows ZIP — **два независимых BAT**, выбирай подходящий. Ни `.ps1`, ни `.js` рядом не нужны. В Linux/macOS ZIP — один скрипт. `README.md` и `LICENSE` — документация, их можно не копировать.

В репозитории файлы находятся в `windows/`, `linux/`, `macos/`, `python/`.

### Windows

Двойной щелчок по подходящему BAT — файлы в его папке сортируются. Окно ждёт клавишу **после** сортировки, чтобы результат не исчезал; подтверждать перемещение не нужно.

```bat
sort-downloads.bat
sort-downloads.bat --dry-run
sort-downloads.bat --path "%USERPROFILE%\Downloads"
```

Для старых Windows используй `sort-downloads-legacy.bat` с такими же параметрами. На XP папки Downloads может не быть: достаточно положить BAT в нужную папку.

Современный BAT исполняет встроенный PowerShell-код, legacy BAT — встроенный JScript. Внешние файлы для этого не создаются. `ExecutionPolicy Bypass` действует только на процесс и не меняет системную политику. Права администратора не нужны. Если WSH/PowerShell запрещены корпоративной политикой, не отключай защиту ради скрипта.

### Linux

```bash
chmod +x sort-downloads.sh
./sort-downloads.sh
```

Или `bash sort-downloads.sh`. Запуск из файлового менеджера зависит от его настроек. `/bin/sh` не подходит: нужен Bash.

### macOS

```bash
chmod +x "Sort Downloads.command"
```

Дальше — двойной щелчок по `.command` или `./"Sort Downloads.command"` в Terminal. Если macOS блокирует файл, проверь источник и используй системное «Открыть» / «Конфиденциальность и безопасность», не отключая Gatekeeper глобально. Для Terminal может потребоваться доступ к «Загрузкам».

### Python

```bash
python sort-downloads.py
# На Linux/macOS команда может называться python3:
python3 sort-downloads.py
```

Один файл, **без `pip install`** и сторонних библиотек. На Windows возможен двойной щелчок, если `.py` ассоциирован с Python. Поддержка конкретной Windows зависит от версии Python; для XP используй legacy BAT.

## Необязательные параметры

- **Без параметров** — сразу сортировать папку скрипта, не текущую рабочую директорию и не автоматически системные «Загрузки».
- `--path ПАПКА` — сортировать указанную папку.
- `--dry-run` — только показать план, без создания папок и перемещения файлов.
- `--apply` — явно включить перемещение; оставлен для совместимости и обычно не нужен.
- `--help` — справка.

Если указаны и `--apply`, и `--dry-run`, действует **последний** флаг. Начиная с **v1.1.0** файлы перемещаются сразу. В v1.0.0 по умолчанию был предпросмотр и требовались вспомогательные файлы.

## Категории

**145 расширений**, регистр не важен: `.jpg`, `.JPG`, `.JpG`, `.HEIC` работают одинаково.

| Папка | Примеры |
|---|---|
| `archives` | ZIP, RAR, 7Z, TAR.GZ, ZST |
| `iso` | ISO, IMG, BIN, DMG, VHD, QCOW2 |
| `music` | MP3, FLAC, WAV, M4A, OPUS, M3U |
| `video` | MP4, MOV, MKV, WEBM, M2TS |
| `programs` | EXE, MSI, APK, DEB, RPM, BAT, PS1, SH, COMMAND, PY |
| `photos` | JPG, JPEG, HEIC, HEIF, TIFF, DNG, CR2/CR3, NEF, RAW |
| `images` | PNG, GIF, SVG, WEBP, AVIF, JXL, PSD |
| `docs` | PDF, DOCX, XLSX, TXT, EPUB, FB2, MD, CSV |

`.dmg` → `iso`, `.tif` / `.tiff` → `photos`. Используется последнее расширение: `archive.tar.gz` → `archives`. Тип определяется по имени, не по содержимому. Для изменения категорий редактируй встроенную таблицу в выбранном скрипте.

## Безопасность и ограничения

- Файлы назначения **не перезаписываются**. При совпадении имён выводится `SKIP`, оба файла остаются без изменений. Автопереименования нет.
- Только обычные файлы верхнего уровня. Подпапки и `.app`-пакеты macOS не перемещаются и не обходятся.
- `.torrent`, `.magnet`, неизвестные расширения, файлы без расширения, `.part`, `.crdownload`, `.download` остаются на месте. Ненужные файлы не удаляются.
- Папки категорий создаются по необходимости. Выполняемый скрипт, включая переименованный, и известные имена инструмента защищены от перемещения.
- Симлинки / reparse points среди исходных файлов пропускаются. Категория-ссылка, junction или обычный файл вместо папки даёт ошибку и не используется.
- Скрытые обычные файлы с известным расширением тоже сортируются. Кириллица, пробелы и специальные символы поддерживаются; содержимое не меняется.
- Не запускай несколько экземпляров одновременно, не подменяй папки/ссылки во время работы. Это не транзакционная система: успешные перемещения до ошибки не откатываются.
- Дождись окончания загрузок: активно скачиваемый файл с окончательным расширением определить невозможно.
- Сетевые диски, права и длинные пути зависят от ОС; у XP обычные ограничения Win32. Первый запуск лучше проверить на копии.

Python перемещает через эксклюзивный hardlink + удаление исходной ссылки. Если hardlink не поддерживается, выполняется эксклюзивное копирование с сохранением доступных `shutil.copystat` метаданных; исходник удаляется только после успешного завершения. При ошибке копирования исходник остаётся. Для резервного способа нужно место под файл; ACL и альтернативные потоки не переносятся через `copystat`.

**Реальная Windows XP не тестировалась.** Legacy использует рассчитанные на XP API и синтаксис; CI проверяет его через WSH на современном Windows.

Коды завершения: **0** — успех / предпросмотр (коллизии не ошибка), **1** — ошибки отдельных файлов или категорий, **2** — неверные аргументы или корневая папка. Итог: `Planned` — кандидаты, `Moved` — перемещённые, `Errors` — ошибки.

## Исходный референс

`reference/original.bat` — побайтовая копия исходника (Windows-1251, исходные окончания строк). `reference/original-readable.txt` — UTF-8-копия для чтения.

**Не запускай референс для обычной сортировки:** он удаляет `.torrent` / `.magnet` и не содержит новых защит. В релизные архивы он не включён.

## Разработка

Для тестов и упаковки нужен Python 3.12+. Конечному пользователю нативных вариантов Python не нужен.

```bash
# После изменения канонических Windows-ядер обнови самодостаточные BAT:
python tools/build_standalone.py
SORTER_VARIANT=linux python -m unittest discover -s tests -v
# macOS: SORTER_VARIANT=macos
# Windows PowerShell: $env:SORTER_VARIANT='modern'  # либо legacy
python tools/build_release.py --version 1.1.0
```

CI проверяет Windows, Ubuntu и macOS, включая запуск **одного изолированного файла**, регистр, Unicode, предпросмотр, коллизии, ссылки, повторный запуск, упаковку и SHA-256. При push тега `vMAJOR.MINOR.PATCH` создаётся черновик релиза; скачанные артефакты нужно проверить перед публикацией.
